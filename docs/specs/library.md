# 书库

> 状态：🚧 导入 / 书架 / 删除 / 合集已实现；排序、搜索规划中。
> 相关：[reading-formats](reading-formats.md)、[platform-and-storage](platform-and-storage.md)

## 1. 已实现

- 拖拽或点选导入（`.epub`）
- 解析并展示元数据：标题、作者、封面
- 书架网格，点击进入阅读器
- 删除书籍（同时清理文件、封面与数据库记录）
- 空状态有明确引导
- 书架顺序：最近阅读优先，未读的按导入时间倒序

**导入的错误处理**（已实现，作为后续格式扩展的基准）：
非 `.epub` 文件、非 zip、合法 zip 但无 `container.xml`、截断文件，
各自给出明确提示，且不污染书架；一次导入多个文件时，坏文件不影响好文件入库。

### 拖拽导入的实现约束

`tauri.conf.json` 里必须保持 `"dragDropEnabled": false`。
Tauri 默认会截获拖放并只给出文件路径；关掉之后 webview 自己处理 HTML5 拖放，
**两个目标共用同一段 `onDrop` 代码**，也不需要为读取任意路径开 fs 权限。
文件选择用原生 `<input type="file">`，同理不需要 dialog 插件。

## 2. 规划

### 排序与筛选
- 排序：最近阅读 / 导入时间 / 标题
- 阅读状态筛选：未读 / 在读 / 读完
- 进度在书架可见（封面上的进度条或角标）

### 搜索
- 书库内按标题、作者搜索
- **书内全文搜索**属于 [reader-view](reader-view.md) 的范畴（已实现），入口可以放在书库

### 组织

**合集（已实现）**：一本书可属于多个合集，因此成员关系是独立的 `collection_books` 关联表，
不是书上的一个字段。

- 书架顶部是合集筛选条：`全部` 常在；`未分类` **只在真的有未分类书籍时出现** ——
  一个用户永远填不满的空桶只是噪音；每个合集显示当前书籍数。
- 新建：筛选条上的「新建合集」就地输入；重命名：双击合集名；删除合集**不删除书籍**。
- 归类：书封悬停出现合集按钮，勾选即归入，一次可归入多个。
- 合集顺序按名称的**码点序**，与 SQLite 的 `ORDER BY name` 一致 ——
  两个存储实现对同一份数据必须给出同样的顺序，排序规则收在 `platform/sort.ts`。
- 被别处删掉的合集若正好是当前筛选项，书架回落到 `全部`，不能停在一个空视图上。

**元数据编辑（规划中）**：修正错误的书名、作者、封面。
真实来源的 EPUB 元数据经常是脏的，这个功能的实际价值比听起来高。

### 多格式
导入需支持 `.epub` / `.txt` / `.pdf`，按内容而非仅扩展名识别，
并在书架上标出格式（因为能力不对等，见 [overview](overview.md#4-格式支持矩阵)）。

### 数据导出
「一键导出全部数据」（书籍元数据 + 进度 + 划线 + 生词），
用于备份与迁移。属于产品的「绝不锁定」原则。

## 3. 明确不做

- 书城 / 内购 / DRM 书籍
- 在线书源、OPDS
- 云端书库同步（跨设备同步在 [overview](overview.md) 的候选功能里，优先走用户自选目录）

## 4. 验收要点

- 三种格式都能导入并正确显示元数据与格式标识
- 畸形文件不进书架且提示明确
- 删除后各类数据（元数据 / 文件 / 封面 / 进度 / 设置 / 书签 / 划线 / 合集归属 / 统计）均不残留
- 删除合集后书籍仍在书库；删除书籍后它从所有合集消失，但合集本身还在
- 排序切换后顺序正确，且与存储层的语义一致
