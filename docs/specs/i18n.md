# 界面语言（i18n）

> 状态：✅ 简体中文 / English 已实现。
> 相关：[platform-and-storage](platform-and-storage.md)

## 1. 范围

**只管界面，不管书。** 菜单、面板、统计页、确认对话框走这一套；
书籍正文、章节标题、划线内容、书名作者一律原样呈现——它们是用户的数据，
不是产品的文案。日期与月份名走 `Intl`，跟随语言解析出的 locale。

支持两种语言：`zh`（简体中文）与 `en`。中文是**源语言**：所有文案先在中文里写，
英文是它的翻译。

## 2. 为什么不用 i18n 库

`react-i18next` 提供的命名空间、懒加载、复数规则表，在这个应用的体量上都用不到；
代价是两个依赖和约 40 kB。这里的方案是一个字典加一个 `t()`：

```
src/i18n/
  messages.zh.ts   源字典，`as const`
  messages.en.ts   类型为 Record<MessageKey, string>
  types.ts         MessageKey / Messages / Translate / Language
  format.ts        {name} 占位符替换
  context.ts       字典选择与 t 的构造
  I18nProvider.tsx
  useT.ts          useT() / useLanguage()
```

**类型即校验**：`MessageKey = keyof typeof zh`，英文字典声明为 `Messages`，
所以在中文里加一个 key 而不翻译，是**构建失败**，不是运行时渲染出 key 本身。
拼错 key 同理。

类型看不进字符串内部，所以占位符一致性由测试守：一条译文漏掉 `{n}`，
渲染出来就是一句缺了数字的话。`messages.test.ts` 逐 key 比对两边的占位符集合。

## 3. 复数

中文没有语法复数，英文有。`t.plural(base, n)` 在 `base.one` 与 `base.other` 之间选，
**0 走 other**，和英语一致。中文两条通常是同一个字符串——这是冗余，但它让
「哪些文案带数量」在字典里一目了然，也让英文那边不必迁就中文的形态。

只有确实会因数量而改写的句子才成对；其余用一个 key。

## 4. 语言解析

```
偏好 auto → 依次扫 navigator.languages，命中 zh-* 或 en-* 即用
偏好 zh / en → 直接用
两者都没命中 → zh
```

跳过不认识的标签而不是停在第一个：系统首选法语、次选英语时，应当给英语而不是回落中文。
兜底是中文，因为那是文案的源语言。

解析结果写进 `document.documentElement.lang`，连字、引号形态与读屏跟着走。

## 5. 组件之外的文案

两处拿不到 `t()`：

- **书库 store**（zustand，不是组件）：错误状态存 `{ key, values }` 而不是成品字符串，
  由视图渲染。副作用是**已经显示在屏幕上的错误也会跟着切换语言**。
- **数据常量**：排版预设名、划线颜色名、字体族标签，存 message key（`nameKey` / `labelKey`）
  而不是字面量，在展示处解析。

## 6. 数量与单位

大数分级属于语言而不属于文案：中文按 **万**，英文按 **million**。
所以除数由语言决定，key 只描述形态（`stats.countLarge` / `stats.countMedium`）。

## 7. 验收要点

- 两份字典 key 完全一致，占位符逐 key 一致，无空串，`.one` 必有 `.other`
- 切换语言后整个界面立即改变，无需重载；书籍内容、划线文本不变
- `auto` 在中文系统给中文、英文系统给英文、法语系统给中文
- 源码中不再存在组件内的中文字面量（`src/i18n/` 除外）
