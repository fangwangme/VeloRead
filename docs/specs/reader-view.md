# 阅读视图：排版、风格、导航

> 状态：✅ EPUB 阅读视图已实现；TXT / PDF 的格式适配见 reading-formats。
> 参照物：Apple Books 的阅读视图与「Aa」设置面板。
> 相关：[reading-formats](reading-formats.md)、[pacer](pacer.md)、[platform-and-storage](platform-and-storage.md)

## 1. 改造基线与目标（实现前实测）

Issue #3 实现前的阅读器**能用但简陋**。下表保留为排版决策的基线证据；当前实现已落地目标列：

| 指标 | 改造前 | 当前目标 |
| --- | --- | --- |
| 每行字符数 | **141** | 45–75（理想 66） |
| 行高 | `normal`（≈1.15） | 1.45–1.75 |
| 字体 | `Times`（浏览器默认） | 明确指定 |
| 页边距 | `0` | 有版心 |
| 目录 | **无** | 必须有 |
| 位置信息 | 仅百分比 | 章节 + 本章剩余 |

对照实验（同一本书只改排版）：容器收窄 + Georgia 19px/1.62 + 两端对齐 + 断词，
每行字符数 141 → **71**，观感从「网页」变成「书」。**排版是投入产出比最高的一项。**

## 2. 排版基准

- **版心（measure）45–75 字符**，理想 66。**必须以 `ch` 为单位配置**，不能用 px ——
  否则用户一放大字号，每行字符数就掉到 40 以下，同样难读。
- **行高** 1.45–1.75；行越长需要越大的行高帮助回行。
- **两端对齐必须配 `hyphens: auto`**，否则英文会出现巨大的词间空隙（「排版河流」）。
- **首行缩进与段间距二选一**，不要同时使用。

## 3. 风格系统

### 3.1 模型：预设 + 覆盖

对齐 Apple Books：选一个主题即整组套用，之后仍可单项微调。

```ts
interface ReadingStyle {
  id: StyleId
  name: string
  palette: {
    background: string
    text: string
    muted: string          // 图注、页眉页脚
    accent: string         // 链接、当前章高亮
    rule: string           // 分隔线、引用左边框
    codeBackground: string
  }
  /** 正文 */
  body: {
    fontStack: string
    fontSizePx: number
    lineHeight: number
    measureCh: number                 // 版心用字符数
    align: 'start' | 'justify'
    hyphens: boolean
    paragraph: 'indent' | 'spaced'    // 二选一
  }
  /** 正文之外的元素 —— 一本书不只有段落 */
  elements: {
    headingFontStack: string          // 可与正文不同（衬线正文 + 无衬线标题很常见）
    headingScale: number[]            // h1..h6 相对正文的倍数
    headingWeight: number
    codeFontStack: string             // 等宽，永远不跟随正文字体
    blockquote: 'indent' | 'rule'     // 缩进 或 左边线
    listIndentEm: number
    tableBorder: 'none' | 'horizontal' | 'all'
    figureCaptionScale: number
  }
}

/** 用户在预设之上的微调；null = 跟随预设 */
interface StyleOverride {
  fontStack?: string | null
  fontSizeStep?: number | null   // 相对预设的档位偏移，不是绝对 px
  lineHeightStep?: number | null
  marginStep?: number | null     // 映射到 measureCh
  bold?: boolean | null
  justify?: boolean | null
}

type ResolvedStyle = /* 预设 覆盖以 override 中的非 null 项 */
```

**关键点**：微调存的是**相对档位**而不是绝对值。这样换风格时用户的「我喜欢大一号」
依然成立，而不是被新预设的绝对值冲掉。

**字号一档 = 1px**，范围足够从任何预设走到渲染层允许的两端（12–36px）。早先一档 2px、
只有九个档位：正文字号恰恰是那个「要一直微调到刚好」的设置，2px 一跳是看得见的跳动，
中间还没有停靠点，而范围又先于渲染边界用尽。当前值显示在 A− / A+ **中间**，就在改它的两个键之间。

### 3.2 预设风格

**只做 6 套经典的**，平铺展示，不分组。

| 预设 | 定位 | 正文字体 | 字号/行高 | 版心 | 对齐 | 段落 |
| --- | --- | --- | --- | --- | --- | --- |
| **书籍 Book** | 默认，暖白纸感 | Georgia / Charter 衬线 | 19px / 1.62 | 66ch | 两端 | 首行缩进 |
| **羊皮纸 Sepia** | 暖色护眼 | Georgia | 19px / 1.62 | 66ch | 两端 | 首行缩进 |
| **现代 Modern** | 现代散文 / 无衬线 | SF Pro / Helvetica | 18px / 1.70 | 64ch | 左对齐 | 段间距 |
| **科学杂志 Journal** | 长文精读 | Palatino / Iowan 衬线 | 18px / 1.75 | 62ch | 左对齐 | 段间距 |
| **报刊 News** | 高密度速览 | Charter / 紧凑衬线 | 17px / 1.45 | 72ch | 两端+断词 | 首行缩进 |
| **中文宋体 Song** | 中文正文默认 | 宋体 / Songti SC | 18px / 1.80 | 40ch | 两端 | 首行缩进 2 字 |

选择依据：经典衬线、暖色护眼、现代无衬线、学术、报刊与中文各覆盖一种长期阅读场景。
深色不是单独的一套风格；每套风格都有对应的 `darkPalette`，由应用级外观统一切换。

**刻意砍掉的**：素白 Plain（「跟随书籍原字体」已经覆盖了「不要风格」这个诉求）、
打字稿 Manuscript（等宽体做长文正文是新奇感，不是经典）。

**暂不分组**：6 套平铺就够，分组反而是多余的层级。等超过 8 套再引入分类。

约束：
- **字体栈必须带回退**。Iowan Old Style / Charter / Songti SC 是 macOS 系统字体，
  浏览器目标会退化到 Georgia / 系统衬线。这是刻意接受的差异（打包 Web 字体会显著撑大产物）。
- 每套 `darkPalette` 的正文对比度需满足 WCAG AA（≥ 4.5:1），但**不要纯白压纯黑**（眩光）。
- 「报刊」指高密度、两端对齐、紧凑行距的观感，**不是多栏排版**。
- **等宽字体永远不跟随正文字体设置** —— 代码块换成衬线体会毁掉对齐。

### 3.3 CJK 排版的特殊规则

中文排版不是「把英文的字体换掉」那么简单，必须单独处理：

- **不断词**：`hyphens` 对 CJK 无意义，必须关闭
- **版心按字数算**：中文一行 35–45 字舒适，对应的 `measureCh` 远小于英文的 66
- **行高更大**：中文方块字没有 x-height 的视觉呼吸，1.75–1.9 才舒服
- **首行缩进 2 个字**（`text-indent: 2em`），这是中文的惯例，不是 1.2em
- **标点挤压**：理想情况下开启 `text-spacing` / 标点悬挂，但浏览器支持不一，
  先不做，也不要假装做了
- **中英混排**：正文字体栈里英文字体放前面、中文字体放后面，
  浏览器会按字符逐一回退，这样英文不会被中文字体里的劣质西文字形接管

### 3.4 参考 docu.md 后的取舍

调研了 [docu.md 的主题目录](https://docu.md/features/themes.html)（29 套，分 Classic /
Reading / Modern / Creative / Chinese / Playful / Nature 七类）。

**采纳：**
- **「每套主题控制什么」的清单**：docu.md 明确覆盖了正文、各级标题、代码块、表格、列表间距。
  这**暴露了本 spec 原先的一个真实缺口** —— 之前的 `ReadingStyle` 只定义了正文。
  一本书还有标题、引用、代码、表格、图注，只管正文会让这些元素在换风格后完全失控。
  §3.1 的 `elements` 字段就是据此补上的。
- **主题身份**：Academic / Newspaper / Magazine 与我们要的观感重合，印证了
  「科学杂志 / 报刊」这两套值得单独存在。
- **中文主题**：宋体 / 黑体 / 仿宋的区分提醒我们**必须单独做 CJK 排版**（§3.3）。

**不采纳，及理由：**
- **29 套太多**，连它的分类体系也一并不要。docu.md 是文档导出工具，每份文档挑一次外观；
  阅读器是配置一次然后长期待在里面的地方。Apple Books 只给 6 套是有道理的 —— 我们也定 6 套，
  平铺展示。
- **Playful 与 Nature 两类全部不要**（Rainbow / Candy / Dinosaur / Space / Garden / Coral…）。
  彩色正文用来读小说是**有害**的，这些是给小学生作业和创意文档用的。
- **Comic Sans / Century Gothic** 不进候选。
- **pt 单位与印刷尺寸**（12pt/11pt）不适用。那是给纸张排版的；屏幕阅读要 px，
  而且**docu.md 完全没有版心/页边距的概念** —— 因为对导出工具来说页宽就是纸张大小。
  但版心恰恰是屏幕阅读**影响最大的单一变量**（实测 141 → 71 字符/行）。
- **docu.md 没有深色模式**。对文档导出无所谓（要打印），对阅读器是硬需求。

### 3.5 可调项（对齐 Apple Books 的 Aa 面板）

| 项 | 形式 | 说明 |
| --- | --- | --- |
| 风格 | 卡片选择 | 上表 6 套 |
| 字体 | 列表 | 从内置字体栈里选，含「跟随书籍原字体」 |
| 字号 | `A-` / `A+` 离散档位 | 不用连续滑杆，档位更好控制 |
| 行距 | 三档（紧/中/松） | 相对预设的档位 |
| 页边距 | 三档（窄/中/宽） | 映射到 `measureCh` |

这三项存的都是**相对档位**，但界面必须同时显示**当前生效的绝对值**（`19px` / `1.62` /
`66 字符`）。只显示「+1」用户无从判断页面会变成什么样，而且档位在被 `resolveStyle` 的上下界
夹住之后就不再对应实际变化。
| 两端对齐 | 开关 | 覆盖预设 |
| 粗体 | 开关 | 可访问性，字重提升 |
| 滚动模式 | 开关 | 见 §5 |

全局外观（跟随系统 / 浅色 / 深色）属于**应用设置**，入口在书库，不放进当前书籍的 `Aa`。
`Aa` 只调整当前书的排版：风格、字体、字号、行距、版心、分栏与分页/滚动方式。
书内 Pacer 面板同样按书保存英文 / CJK 速度与块大小覆盖，但与 `Aa` 分开呈现；恢复默认后继续
跟随应用设置里的两套 Pacer 全局值。

**「跟随书籍原字体」很重要**：有些书（诗集、技术书、带代码块的书）自带排版是有意义的，
强行覆盖反而更糟。Apple Books 的 `Original` 就是这个作用。

**首次打开一本书时按语种选默认风格**：`dc:language` 是 `zh*` 则默认「中文宋体」，
否则默认「书籍」。之后以用户的按书设置为准。

### 3.6 覆盖强度

书自带 CSS，覆盖需要 `!important`；个别书还有内联样式。策略：
- 默认覆盖 `font-family` / `font-size` / `line-height` / `color` / `background`
- **不覆盖**：`<code>`/`<pre>` 的等宽字体、行内强调、表格结构、图片尺寸
- 「跟随书籍原字体」时只覆盖颜色与版心，不动字体族

## 4. 导航

- **目录 TOC**：侧边抽屉，嵌套章节，高亮当前章，点击跳转。
  面板按 Apple Books 分页签组织：**目录 / 书签 / 划线**，三个页签都显示条目数。
  划线条目展示颜色条、原文、笔记与所属章节，点击跳转；来自导入、无法定位的条目
  不提供跳转按钮（见 [annotations](annotations.md)）。
- **位置信息**：`第 3 章 · 本章还剩 8 页 · 全书 37%`。
  「本章还剩 N 页」比一个全书百分比有用得多。
  进一步可结合 Pacer 的真实速度给出「本章还剩约 12 分钟」（见 [pacer](pacer.md)）。
- **书签**：手动书签，存 `Locator` + 摘要文本。摘要取当前页开头的正文文字，
  取不到才退回章节名 —— 整章共用同一个章节名会让书签列表完全无法区分。
- **跳转历史**：从目录/书签/搜索结果跳转后可一键返回原位（一层跳转栈即可，不做完整历史）。

### 书内全文搜索

EPUB 没有内置索引，epub.js 也不提供全书搜索。实现方式是**按需逐章遍历**：依次
`section.load()` → `section.search()` → `section.unload()`，用完即卸，内存不随书变大。
代价是搜索过程可见，因此：

- **显式提交**（回车或按钮），不做输入即搜 —— 每次击键都触发一次全书扫描是不可接受的；
- 展示章节级进度条，并提供**停止**按钮，用 `AbortSignal` 中断；
- **停止保留已经搜到的结果**，并标明它们只覆盖已扫描的章节。中断的意思是「不用再找了」，
  不是「作废」；把扫了半本书的命中丢掉，等于把「停止」做成了「取消」；
- 面板关闭时中断在途扫描，不让大部头在后台继续加载 spine；
- **不卸载正在渲染的那一章**：`Section.unload()` 清掉的是 live view 持有的同一个对象上的
  `document` / `contents` / `output`。进来时已经加载的章节，出去时保持原样；
- 单次结果上限 300 条，达到上限要**明确告知**，不能静默截断；
- 用 `section.search()` 而不是 `find()`：前者会拼接连续文本节点，跨 `<em>` 或换行的短语
  也能命中；
- 加载失败的章节跳过即可，不能让一章打不开就中断整次搜索；
- 结果显示上下文摘录（命中词高亮）与所属章节，点击跳转并记入跳转栈。

搜索面板与目录、Aa 一样属于阻塞面板：打开时 Pacer 暂停且不计入阅读时长。

### 翻页热区

「没有文字的地方都可以翻页」，左半边回退、右半边前进。空白分两处，分别处理：

- **书页之外**（版心两侧的留白）：翻页区是版心的 flex 兄弟节点，不是浮在阅读面上的遮罩。
  早期实现用两条 12.5% 宽的绝对定位遮罩，窗口一宽就压在正文外缘上 —— 那一带不只是误触，
  是**指针事件根本到不了 iframe，划线连起手都起不来**。兄弟节点从结构上杜绝这种重叠。
- **书页之内**（epub.js 自己的栏间距、正文下方）：由书内点击回调判断。
  **不能只看 `caretRangeFromPoint` 是否返回结果** —— 它会吸附到任意远处的最近文字，
  点在页边空白照样返回一个词。必须用几何判断点是否真的落在该词的矩形内：
  水平方向容差要小（页边空白正是要识别的目标），垂直方向放宽一整个行框，
  否则同段两行之间的行距会被误判成空白而翻页。

翻页区最小宽度 48px，保证窄窗口下仍有可点区域。Pacer 播放中、目录 / 排版 / 搜索面板打开时热区失效；
划线浮层打开时热区仍然生效，因为点空白正是关掉它的方式 —— 此时只关浮层，不翻页。

### 4.1 分栏由版心决定，不由一个常数决定

**双栏只在每一栏都还装得下一个完整版心时才成立。** 装不下的话，它就是同一段文字被切成更短的行
——更差，不是更密。所以「什么时候上双栏」这个阈值必须从当前排版真正的版心宽度算出来，
`minSpreadWidth = 单栏版心 × 2 + 栏距`，而不是写死一个数。

写死 860 的后果（实测，1280 宽的窗口、19px）：

| | 容器 | 每行字符数 |
| --- | --- | --- |
| 自适应 / 双栏 | 1184 | **49** ← 低于 55–75 下限 |
| 单栏 | 807 | 75 |

也就是说单栏是当时唯一正确的那个，而默认的「自适应」一直在给过短的行。修正后同一窗口下
自适应给 1 栏 75 字符；把字号调到 13px、两栏各自装得下版心时，它才切成 2 栏 × 71 字符。

**容器宽度和栏数必须同时决定。** 只改栏数、容器仍按双栏留宽，会得到「1 栏铺满 1184px、
每行 160 字符」——比原来更糟。

阈值随字号和页边距变化，所以它由一个 effect 推给渲染层，而不是只在用户切换分栏模式时推一次；
否则改完字号，渲染层还拿着开书时算出来的旧阈值。

## 5. 阅读模式

- **分页**（默认）：CSS 多栏，左右翻页
- **滚动**：连续滚动。**注意 Pacer 在滚动模式下需要另一套推进逻辑**（见 [pacer](pacer.md)）
- 分栏支持自适应 / 单栏 / 双栏，切换时保持 CFI 并重算 Pacer 几何
- 翻页动效暂不做（会干扰 Pacer 的位置计算）

## 6. 键盘与手势

| 键 | 行为 |
| --- | --- |
| `→` / `PageDown` | 下一页 |
| `←` / `PageUp` | 上一页 |
| `Esc` | 返回书库 |
| `空格` | Pacer 播放/暂停（须阻止默认滚动） |
| `T` | 打开目录 |
| `Aa` 面板 | 通过工具栏或快捷键唤出 |

**书页渲染在 iframe 内，window 上的监听拿不到书页里的按键**。
所有阅读快捷键必须同时绑到 window 与书页 document 两处。

### 6.1 横向滑动翻页

触控板双指横扫或妙控鼠标横向滑动翻一页。方向遵循 macOS 自然滚动：内容向左走（`deltaX > 0`）
是下一页。

- **判定与方向键同源**：播放中进/退一块，否则翻页；面板打开或书未就绪时不响应。
  两条输入路径共用一个函数，不各写一套。
- **一次挥手 = 一页**。一次挥手会产生几十到上百个带惯性衰减的 wheel 事件，
  所以是「累积到阈值触发一次 → 上锁 → 直到一小段时间没有横向事件才解锁」，
  而不是按事件数或固定像素数翻页。阈值与释放时长是 `reader/swipe.ts` 里的具名常量，纯逻辑、可单测。
- `|deltaX| <= |deltaY|` 当作纵向滚动**忽略**（平局算纵向）；横向事件 `preventDefault()`，
  否则 WKWebView 会把横扫解释成「返回」手势。
- `deltaMode` 非像素时先换算，不能把行数当像素累加。
- **`wheel` 不跨 iframe 冒泡**，与按键同理：书页 document 与父文档的阅读容器**两处都要挂**，
  但共用**同一个累积器**（在渲染层里），否则各累各的会一次翻两页。
  两处事件的时间戳也必须来自同一个时钟——iframe 有自己的 time origin，`event.timeStamp` 不能混用。
- **滚动模式不支持**，与 `blankSideOfPage` 在滚动模式返回 `null` 是同一个取舍：那里没有「页」可翻。

## 7. 渲染层边界

所有 epub.js 调用收敛在单一渲染模块内。epub.js 的 CFI 与分页有已知毛病，
整体替换渲染层是以后的独立决策，把它关在一个模块后面就是为了让那次决策可控。

固定配置：`flow: 'paginated' | 'scrolled-doc'`、`spread: 'none'`、
`allowScriptedContent: false`（书页是不可信 HTML，没有理由让它执行脚本）。

### epub.js 的坑（实测，必须遵守）

1. **`themes.select()` 是互斥的** —— 连续 select 两次只有最后一次生效。
   旧实现正是这么写的，这就是「定义了 6 套主题却只落地 3 套」的真正原因。
   **正确做法：把风格 + 用户微调合并成一份 rules，注册为单一主题再 select。**
2. **`book.locations` 是边生成边填充的** —— `locations.length() > 0` 不代表当前 CFI 已被索引，
   对未索引的位置 `percentageFromCfi()` 会返回一个看起来正常的 `0`。见 §8。
3. **`ResizeObserver` 在 `observe()` 时必定触发一次** —— 拿刚排过版的同一尺寸再排一次，
   会让 CFI 恢复差整整一页。必须跳过尺寸未变化的回调。
4. **改排版后必须重算所有叠加几何**（Pacer 高亮、划线框）。

### 7.1 屏幕外隐藏文本必须就地纠正

书籍常用一个正确的无障碍写法把文字藏起来给读屏用（Standard Ebooks 的每个扉页、版权页、
出版说明都用）：

```css
section[titlepage] h1, section[titlepage] p { position: absolute; left: -999em; }
```

epub.js 用 `range.getBoundingClientRect().width` 量一节的内容宽度，而这个包围盒会从被藏起来
的元素一直张到最后一个字。`-999em` 在 34px 的标题上是 −33966px，于是**一个扉页被量成
34740px 宽、分成 41 栏，其中 40 栏是空的**——这就是「莫名其妙几十页空白」的来源。
**不是书的问题，也不是解析的问题**，是这个写法撞上了 epub.js 的测量方式。

内容注入钩子里就地把它换成现代的 clip 写法：盒子回到原点、1×1、`clip-path: inset(50%)`。
**`display` 和 `visibility` 不动**——那会把元素从无障碍树里摘掉，正好毁掉书想要的东西。

先做一次 Range 测量作为廉价探针，没有这个写法的章节一分开销都不付。

实测（Meditations，807px 版心）：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 量得的内容宽度 | 34740px | 774px |
| iframe 宽度 | 35508px | 1614px |
| 栏数 | 41 | 2 |

## 8. 进度百分比

`progress` 的类型是 `number | null`，**`null` 表示「还不知道」，不是「在开头」**。

由来：epub.js 的 locations 未生成完时 `percentageFromCfi()` 返回 `0`，
把它当真写回存储会导致「打开一本读到 50% 的书，进度被改写成 0%」——
这个 bug 实际发生过。规则：

- 只有 locations 生成**完成后**读到的数值才算数
- 收到 `null` 时保留上一个已知值（打开书时用存储里的旧值播种），绝不当 0 写回

## 9. 行为契约

- 进度：每次位置变化记录 `Locator`，防抖 400 ms 落库；离开阅读器时立即冲刷
- **离开应用时冲刷**：`beforeunload` 在 WKWebView 里基本不触发，所以「应用要走了」是一次与 Rust
  的握手——Tauri 挡下关闭（`CloseRequested` / `ExitRequested`），发事件让前端把进度与阅读时长
  写完，前端回报后再真正退出。**Rust 侧有宽限期**（当前 1.5 s）：webview 卡住的代价必须是退出
  慢一下，绝不能是退不掉。这条能力走 `platform` 的 `LifecyclePort`，前端不直接调 Tauri window API。
- **Cmd+Q 拿不到这个机会（实测，macOS 15 + Tauri 2.11）**：`NSApplication` 的 terminate
  （Cmd+Q、Dock 上的「退出」、外部 quit 事件）只发 `RunEvent::Exit`，既没有 `ExitRequested`
  也没有窗口 `CloseRequested`，而 `Exit` 无法推迟。要挡住它得替换标准的 Quit 菜单项或接管
  `applicationShouldTerminate`，那是比这个钩子更大的决定。
  因此**前端把「能丢多少」压小**，而不是指望退出时的最后一次写：页内光标位置最多每 2 s 落库，
  窗口失焦与 `visibilitychange` 时立即冲刷。最坏情况是丢掉一行半的阅读位置。
- 自动阅读时进度记到**词**一级（光标所在词的 CFI），详见 [pacer §10.0](pacer.md)
- 重排：容器尺寸变化防抖 150 ms 后按像素尺寸重新排版（须跳过尺寸未变的首次回调）
- 恢复：重开一本书从存储里的 `Locator` 恢复；无记录则打开首页
- **书还没打开完就离开阅读器时，丢弃迟到的位置回调** —— 那是首屏位置，写下去会把阅读位置推回开头
- 书架顺序依赖 `lastReadAt`，由阅读器在最后一次进度写入落地**之后**刷新书库
- 改风格/字号后**阅读位置不能丢**
- **剩余时间以当前页为尺**：EPUB 没有字数可查，数一遍要先把整个 spine 分页。所以量当前页
  读完要多久，再按「本章剩余页数」和 epub.js 位置索引给出的「全书剩余字符数」分别放大。
  两个估算共用同一把尺；位置索引是千字粒度的粗刻度，因此全书估算**不得小于本章估算**。
- **排版按语言存，不按书存。** 一套中文设置、一套英文设置，由书的 `language` 元数据决定用哪套。
  按书存意味着调好一本、下一本又回到默认，而用户调的是**自己的阅读习惯**，不是某一本书的属性。
  这和 Pacer 早就采用的形状一致：一个引擎、两套语言参数。
  分页/滚动是全局一个选择——它关乎你怎么读，与脚本无关。
  Aa 面板的标题会写明当前编辑的是哪一套（「中文书籍排版」/「英文书籍排版」），
  否则用户无从知道这次改动波及多少本书。
  `book_settings` 的 `style_id` / `overrides` / `flow` 列不再被读取，仅为兼容旧 schema 保留。
- **窗口尺寸与位置要记住**：阅读器是一个「按自己眼睛调好一次、明天还应该是那样」的窗口。
- **顶栏可拖动窗口**：窗口用 overlay 标题栏且隐藏标题，没有原生标题栏可抓，必须显式声明拖动区；
  拖动区只在承载该属性的元素上生效，所以按钮仍然可点。
- **破坏性操作一律走应用内确认框，不用 `window.confirm`**：wry 的 `WKUIDelegate` 没有实现
  `runJavaScriptConfirmPanel`，打包后的 WKWebView 不弹任何东西、`confirm()` 直接返回 `false`，
  按钮于是永远不生效。确认框的焦点默认落在「取消」，删除按钮不抢第一个焦点位。
- **抽屉与面板是模态**：目录抽屉、搜索面板、划线卡片与书库的两个 modal 一样有焦点陷阱和 `aria-modal`
- **顶栏自动隐藏有一个例外**：只要存在「跳转前的位置」，顶栏就不自动淡出——返回入口不能跟着消失，
  详见 [annotations §5.1](annotations.md)
- **应用设置的排列顺序**：设一次就不再动的（外观、语言、每日目标）在前，两组自动阅读参数居中，
  只读不改的放最后——按键与手势速查表，然后是「关于」（版本号取自 `package.json`，构建时注入，
  不在界面里另抄一份）。
- **按键与手势必须在应用里可查。** 空格、方向键、T / A / F、横向滑动翻页、点正文定位、点空白翻页、选中划线
  ——这些界面上没有任何提示，不写下来就只有作者知道。应用设置里有一节常驻列表；用一次就消失
  的引导提示不算数，「这东西能干什么」这个问题会反复出现。
- **点击正文定位是可关的。** 默认开启；关掉后点正文不做任何事（翻页仍由空白区域负责）。

## 10. 验收要点

- 六套预设逐一截图；默认字号下每行字符数落在 55–75
- 字号调到最大/最小时版心随之变化，字符数仍在 45–80
- 改预设/字号/窗口大小后阅读位置不丢
- 目录能列出全部章节并正确跳转，当前章高亮正确
- 位置信息显示章节名、本章与全书的**剩余时间**，以及全书百分比
- **书架显示阅读进度**：读过的书在封面底部有一条进度条，旁边写百分比。
  不足 1% 的不显示——那既可能是没读过，也可能是 epub.js 还没生成 locations 时写下的 0，
  而封面下方一个「0%」比空白说得更少。
- 书签可增删跳转，跳转后能一键返回原位
- 滚动模式下能连续读完一章并正确记忆位置
- 键盘操作在书页内（iframe 聚焦时）同样生效
- 横向滑动在书页正文上与页边空白处都能翻页，一次挥手只翻一页；纵向滚动不翻页；滚动模式下不翻页
- Cmd+Q 退出后重开，阅读位置不回退（最多差一行半，见上）；关窗口退出则一字不差
- 删除书籍 / 合集 / 书签 / 划线都会先问一次，取消后数据仍在
- 界面语言切换后阅读器 chrome、抽屉、面板全部改变，正文与划线内容不变
