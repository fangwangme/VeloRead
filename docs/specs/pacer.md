# 自动阅读（Pacer）

> 状态：✅ EPUB 已实现；TXT / PDF 随对应格式渲染层落地。
> 相关：[reader-view](reader-view.md)、[reading-formats](reading-formats.md)

## 1. 这是什么

按设定速度自动推进一个高亮块，引导视线移动，**训练打破默读习惯**。

产品定位要诚实：**这是训练工具，不是「一小时读完一本书」的魔法。**
研究表明超过约 500 wpm 后理解率显著下降。Pacer 的现实目标是
**把 240 wpm 拉到 350–450 wpm**，而不是鼓吹 1000 wpm。

## 2. 阅读速度基准

- 成年人英文默读：**非虚构 ≈ 238 wpm，虚构 ≈ 260 wpm**（Brysbaert 2019，190 项研究的元分析）
- 常见区间 175–300 wpm；默读的生理上限约 300–400 wpm
- 一次注视（fixation）大约覆盖 **2–3 个词** —— 这是「3 词一组」的由来

**英文默认值**：250 wpm，范围 100–1000，块大小默认 3 词（可选 3 / 4 / 5 / 整行）。
**1 词与 2 词的档位已删除**：一次注视本来就覆盖 2–3 个词，一次推一个词不是快读而是逐词爬行；
它还逼出了「1 词/块时上限 600 wpm」这条只为守住 100 ms 下限而存在的例外，一并没了。

**中日韩另算**：不能和英文共用一个 wpm 数值。中文默读约 250–350 **字**/分钟，
按 Unicode 字素分块（默认 4 字，可选 4 / 6 / 8 / 10 / 整行），默认 300 字/分钟。

产品模型是**一个 Pacer 引擎、两套语言参数**，不是两种自动阅读模式。应用设置保存英文与 CJK
全局默认值；未单独设置的书跟随全局值，书内 Pacer 面板的调整只覆盖当前书籍。正文风格（例如
“中文宋体”）不参与语言判断，避免“英文书用了宋体就按字计速”。

> UI 上应对高档位给出提示：超过 ~500 wpm 时理解率会下降。
> 让用户知道自己在做取舍，而不是默认以为 1000 可用。

## 3. 视觉形式：移动高亮块

3 词一组的色块沿行平滑移动，**整页文字始终可读**，块走到行末跳到下一行行首。

选它而不是 RSVP（单词定点闪现）的理由：RSVP 速度上限更高，但会脱离书页排版，
不再是「读书」；移动高亮块保留上下文，更接近真实的眼动训练。

### 3.1 样式可调

这条高亮会在正文之上停留数十分钟，**它的观感必须由用户决定**，而不是被排版预设绑死。
应用设置提供三项，作用于全局：

| 设置 | 取值 | 默认 |
| --- | --- | --- |
| 颜色 | `auto`（跟随当前排版风格的 accent）或任意 hex | `auto` |
| 浓度 | 0.04–0.5 的填充不透明度 | `0.18` |
| 形态 | `block` / `block-underline` / `underline` | `block-underline` |
| 同时标出整行 | 开 / 关（`pacerCursorMode`: `chunk-in-line` / `chunk`） | 关 |

默认值与可调之前的观感完全一致。深色页的填充在解析时统一加 `+0.04`，
是**推导出来的偏移而不是第二个设置**，避免两个值各自漂移。
形态选 `underline` 时填充为 `transparent`，浓度滑杆随之禁用——留一个不起作用的控件比没有更糟。

### 3.2 「一次读多少」只有一个控件

**整行是块大小的一个档位，不是另一套模式。** 块大小与「是不是整行」是同一个问题的两种答案，
拆成两个控件（块大小 + 光标范围）就会出现「块大小选 3 词、光标范围选整行」这种自相矛盾的组合，
只能靠互相禁用来补救——那是设计错了，不是交互不够。

- 一个分段控件：`3 词 / 4 词 / 5 词 / 整行`（CJK 是 `4 / 6 / 8 / 10 字 / 整行`）。
  整行用哨兵值 `0` 存（`PACER_CHUNK_SIZE_LINE`），因为按书设置那一列是 INTEGER，
  而且没有别的计数会等于 0。读取时低于最小档位的旧值按最小档位处理。
- 混排页取**当前页主语言那一套**的档位决定是否整行，与控制面板展示哪套参数是同一个判断。

**「同时标出整行」是另一个问题**：光标覆盖多少是上面那个控件的事，这个开关只决定要不要给
光标所在的那一行再铺一层更浅的底（尺子）。选了整行档位时它自然无事可做。

- 行浅底的浓度由同一个浓度设置乘 `0.45` 推导，**不是第二个滑杆**——理由与深色偏移相同。
  形态选 `underline` 时行浅底仍然是填充：它要回答「我在哪一行」，再加一条线做不到这件事。
- 与设置面板的实时预览共用 `overlayStyle.ts` 的同一个解析器。

解析规则在 `pacer/overlayStyle.ts`，纯函数、可单测；设置面板的实时预览与书页走同一个解析器，
所以预览里看到的就是翻开书之后的样子。

## 4. 核心方案：不碰 DOM

**旧实现的做法与失败原因**（453 行，满屏 `CRITICAL` 注释）：
把每个词都包成 `<span class="pacer-word">`，**改写了书的 DOM**。后果：
CFI 锚点受影响、与划线/划词功能直接冲突、整页数百个 span 的开销、翻页后全部失效要重包；
还要用 `offsetLeft` 逐层累加去猜元素在分页坐标系中的位置。

**新方案：Range 几何 + 覆盖层。**

```
遍历文本节点 → 每个词做一个 Range（零 DOM 改动）
  ↓ range.getClientRects() 拿几何
按 N 词分组，跨行则断组（行感知）
  ↓ 换算到父文档坐标
在 iframe 之上叠一个绝对定位的高亮块，CSS transition 平滑移动
```

**已验证**（真实 epub.js 页面）：整章 2802 词 → 当前页 450 词 → 153 个注视块，
高亮块精确落在目标词上。

三个好处：
- **不动 DOM** → 不影响 CFI，不和划线/划词打架
- **覆盖层在父文档** → 动画完全可控，不受 iframe 样式干扰
- **几何来自 Range** → 不必与 epub.js 的分页坐标系搏斗

> 备选方案 CSS Custom Highlight API（`CSS.highlights` + `::highlight()`）更优雅，
> 但需 Safari 17.2（≈ macOS 14），而 `minimumSystemVersion` 是 13.0。**不采用。**

## 5. 模块划分

避免重演旧版 453 行巨兽：

```
chunker.ts    纯函数：文本 run[] → 注视块[]（可单测，不依赖 epub.js）
tokenizer.ts  Unicode 分词：文本节点 → 英文词 / CJK 字素 / 标点
geometry.ts   纯函数：块 → 父文档坐标矩形（可单测）
engine.ts     计时状态机：play / pause / seek / 翻页续接
overlayStyle.ts 纯函数：用户设置 + 排版 accent + 明暗 → 高亮的实际样式（可单测）
Overlay.tsx   高亮块渲染与动画
usePacer.ts   薄封装，把 engine 接到 React
```

文本与几何统一由 `ReaderHandle.getVisibleWords()` 提供（未来格式统一接口见
[reading-formats](reading-formats.md)），Pacer hook 不直接遍历书页 DOM。

`getVisibleWords()` 先按整个文本节点做一次视口裁剪，再对留下的节点逐 token 取矩形；
**裁剪一无所获时回退到不裁剪的整轮测量**——裁剪建立在「整个文本节点的 `getBoundingClientRect()`」
之上，而各引擎对 CSS 多栏里的这个矩形并不总是一致，引擎分歧的代价应该是几帧，而不是让 Pacer
拿不到任何可推进的东西。
分页模式下一页只占章节的一小部分，**逐 token 建 Range 会把整章的布局全算一遍**，
单文件长章节每翻一页就是上万次强制重排。节点级矩形是各行盒的并集，只会多留不会漏。

## 6. 分块规则

- 英文：默认 3 词/块（可选 3 / 4 / 5 / 整行）
- CJK：默认 4 个 Unicode 字素/块（可选 4 / 6 / 8 / 10 / 整行），使用独立 CPM；
  尽量不在分词边界中间断块
- 中英混排：每个块按自身脚本选择 WPM 或 CPM；当前页主语言只决定控制面板展示哪套参数
- `dc:language` 只在当前正文恰好两类数量相同时作回退，缺失或错误的元数据不影响正文判断
- 全角标点、弯引号、Emoji 与符号不计阅读量；句号等强标点为所在块增加自然停顿
- 分词与 DOM Range 偏移使用 `Intl.Segmenter` 的 UTF-16 索引，不能按 `text[index]` 遍历，
  否则扩展区汉字与组合字会被拆坏
- **行感知**：块不跨行；行末不足一块则单独成块
- **断词的词算一个词，但要画两处**：两端对齐的英文开着 `hyphens: auto`，一个词会被排版拆成
  行末的 `con-` 与下一行行首的 `tinued`。它仍是一个词、一次读完，所以**计数只算一次**，
  但高亮必须同时覆盖两截 —— 只画 `getClientRects()[0]` 的话，每个断词的后半截都不会亮，
  看上去就像那一行开头被跳过了。
  测量时保留一个词的全部矩形（连字符本身也是一个独立矩形，与前半截同行合并），
  块因此带一组 `lineBoxes`：**它触及的每一行各一个盒子**，通常只有一个。
  词属于哪一行、哪一栏，仍由它的第一个矩形决定 —— 那是它被读到的位置。
- **分栏感知**：一行的定义是「`top` 相近**且栏序号相同**」。分页模式是 CSS 多栏布局，
  左栏第 N 行与右栏第 N 行的 `top` 完全相同，只看 `top` 会把左栏行末与右栏行首连成一块，
  高亮横跨整页。栏序号取 `floor((rect.left + rect.width / 2) / 栏距)`。
  栏距由 `ReaderHandle.getColumnPitch()` 从书页 body 的 `column-width` / `column-gap` 与内容宽度
  推回（CSS 的实际栏数不总等于 epub.js 请求的栏数，单栏页也带着一个整幅宽的 `column-width`）。
  **取不到栏距时退回只看 `top` 的旧行为**——滚动模式、读取失败都走这条路，
  丢掉分栏感知可以，丢掉块不行。
- **整行档位**（块大小 = `整行`）：行内不再按块大小切分、不因强标点或脚本切换断组，
  一行 = 一块；行感知与分栏感知照旧生效
- 跳过：`<script>`/`<style>`、纯空白、图注等非正文（标签黑名单）
- 标题、列表项独立成块，不与正文混在一组

## 7. 计时

```
dwell = (块内拉丁词数 / wpm) * 60000 + (块内 CJK 字素数 / cpm) * 60000 + 标点停顿
下限 100 ms                          // 防止高 wpm 下变成闪烁
动画时长 = min(dwell * 0.5, 180 ms)  // 动画绝不能长过停留时间
```

块**分别累计两类阅读单位**而不是带一个 `unitKind`：整行模式下中英混排的行是常态，
一个块必须能同时按两套速率计时。纯拉丁 / 纯 CJK 块的结果与这条公式出现之前逐位一致。

## 8. 翻页续接

旧实现最容易出 bug 的地方：

- 当前页的块走完 → 触发下一页
- 页面就位后**重新分块，从新页第一块继续**，不重置播放状态
- 需要「翻页中」锁防止重入
- **暂停时不得覆写阅读位置**

**滚动模式**：没有「翻页」这个事件，改为「高亮块接近视口底部时平滑滚动」。
这是一套**独立逻辑**，是本模块最容易被低估的部分。
当前实现会收集当前 spine section 的正文块，并在高亮接近视口边缘时平滑滚动；章节结束后再进入
下一 spine section。不能只收集当前可见片段后直接 `next()`，否则会跳过本章尚未滚入视口的正文。

### 8.1 翻页必须等 `relocated`

`rendition.next()` 的 promise **早于 `relocated` 事件** resolve：epub.js 的 `reportLocation()`
只是把一个 `requestAnimationFrame` 排进队列，入队函数本身立刻返回，队列不等这一帧跑完。
所以在 `await rendition.next()` 之后直接读位置，读到的仍是**翻页前**那一页——判定「没翻成」，
引擎随即暂停。

Blink 常常赢下这个竞态，WebKit 不会，于是症状是「浏览器里好好的，打包成 app 之后每翻一页
就停」。**翻页必须显式等 `relocated`（带超时兜底，否则一次空翻会把 Pacer 永远挂住）。**

## 9. 必须重算几何的时机

漏掉任何一条都会出现「高亮块留在原地」的可见 bug（spike 中已复现）：

- 翻页 / 滚动
- 窗口或容器 resize
- **切换风格、改字号、改行距、改版心**
- 字体加载完成（`document.fonts.ready`）

## 10. 交互

- `空格` 播放/暂停（阻止默认滚动）
- `←` / `→` 退/进一块
- 触控板 / 妙控鼠标横向滑动：与 `←` / `→` 同一套判定（播放中进/退一块，否则翻页），
  详见 [reader-view §6](reader-view.md)
- 点击或选中正文不修改 Pacer 光标。双击 / 拖选完整交给查词与划线；单击正文不做 Pacer 定位。
  「开始自动阅读」永远是显式动作（播放按钮或空格）。
- 点击书内链接由 epub.js 正常跳转并暂停 Pacer，新位置完成后再重算文字范围
- 播放期间禁用页边、底部整页翻页和跳回按钮，避免绕过 Pacer 后继续引用上一页的文字范围
- 控制面板：根据当前页主脚本展示对应的速度（100–1000）与块大小（含「整行」）；
  混排块自动使用另一套参数
- 打开目录 / 排版面板 / 划线浮层，或应用隐藏、失焦时，Pacer 立即暂停且不后台翻页；
  恢复播放必须由用户主动触发
- Pacer 自身的设置浮层是例外：播放中调整速度或块大小时保持播放并映射到当前文字，但浮层打开期间保守地不授予整页阅读量
- **`prefers-reduced-motion`**：关闭滑动动画，改为直接跳变

### 10.0 每页从开头开始

进入或恢复一页时，Pacer 光标默认位于**当前可见页的第一块**。点击、双击、拖选、划线和查词
都不能修改它；只有 Pacer 自己的播放推进和播放中的前后块控制可以移动页内光标。

暂停后在同一页继续播放时保留 Pacer 自己已经走到的位置；手动翻到另一页后重新从新页第一块开始。
排版重流只把 Pacer 光标重新贴回原来的文字，不算一次人为定位，也不写入新的阅读位置。

**跨会话恢复到页。** Pacer 播放期间仍可把读到的词 CFI 写入 `ReadingProgress.cfi`，这样重开书时
`display(cfi)` 能落到包含它的那一页；但恢复完成后不再 `seek` 回该词，Pacer 从该可见页第一块开始。
数据形状不变，写入的仍是点 CFI，位置索引与百分比语义不受影响。

写入频率是刻意压住的：光标一秒动两三次，但**页内位置最多每 2 秒落库一次**（内存里始终是最新的），
再由离开阅读器、窗口失焦与退出时的冲刷收尾。最坏情况丢一行半，而不是整页。
之所以是「小间隔」而不是「懒写 + 退出时补」，见 [reader-view §9](reader-view.md)：
macOS 的 Cmd+Q 不给任何可推迟的退出通知。

硬约束：**暂停时不得覆写阅读位置**。只有 Pacer 播放推进和播放中的前后块控制会写入；
重排、翻页后把光标重新贴回同一批词（`ChunkChangeCause` 为 `set`）不写，正文交互也不写。

### 10.1 焦点与空格键

**「推进」和「计数」是两件事，不能用同一个开关。**

早先的实现在窗口失焦时直接暂停 Pacer，理由是失焦不该计入阅读时长——但那是通过**停掉被测量的东西**来保证测量准确。代价是多窗口用户根本用不了 Pacer。两者现在分开：

| | 失焦但可见 | 被隐藏（最小化 / 切 Space / 隐藏应用） |
| --- | --- | --- |
| Pacer 推进 | ✅ 继续 | ⛔ 暂停 |
| 计入阅读时长 | ⛔ 不计 | ⛔ 不计 |
| 整页阅读量记账 | ⛔ 不记 | ⛔ 不记 |

隐藏时暂停不是为了统计，是因为隐藏窗口的定时器会被节流到约每秒一次——「继续跑」在那里本来也跑不准，只会在没人看的时候一顿一顿地把书翻完。

**空格键是传送控制键，属于 Pacer，与哪个控件持有焦点无关**（视频播放器就是这个约定）。此前 `button` 和 `a` 也在「可交互元素」排除名单里，于是点过任意顶栏按钮之后，空格会在到达 `preventDefault()` 之前提前返回，浏览器原生的「空格激活聚焦按钮」接管——空格实际变成了**重新点击你上次点的那个按钮**。那是播放键就像是好的，是「目录」就变成开抽屉，表现为「有时能用有时不能」。

排除名单现在只留真正的文本输入。面板打开时空格归面板自己的按钮（打开面板本来就已经暂停了 Pacer）。代价是键盘用户不能用空格激活聚焦按钮，回车仍然可以。

## 11. 与阅读统计的关系

Pacer 是「训练工具」，没有统计就不成立。应记录：
每次会话的实际吞吐 wpm、时长、书籍。用于速度趋势，
以及 [reader-view](reader-view.md) 里「本章还剩约 N 分钟」的个性化估算。

基础时长、英文词数 / CJK 字符数、连续天数与自动打卡已实现，见
[reading-activity](reading-activity.md)。
按会话的真实吞吐速度趋势仍是后续增强项。

## 12. 验收要点

- 250 wpm 下实测吞吐 **240–260 wpm**（计时验证，允许 ±5%）
- 同一页中英混排时，英文块用 WPM、CJK 块用 CPM，互不套用错误参数
- 全角标点、弯引号、扩展区汉字和组合字的 Range 与计数正确
- 高亮块精确覆盖目标词（截图比对，边界偏移 ≤ 2px）
